# Frontend

React 18, TypeScript (strict), Vite 6, Vitest 3. Code: `frontend/src/`. Visual system and rules: `design.md`.

## Structure

| File | Job |
|---|---|
| `App.tsx` | state: health, wing catalog, projects, selected project, view (`phase`, `trace`, `activity`, `folder`), step, focus, messages, artifacts, trace, changes (loaded with every step: an open change decides the redo order), events, folder status; polling of the activity log and the folder; create-and-start; **Accept** (`accept`: approve, then what `afterAccept` says: redo the next step, start the next generator when it has no choices, open a step that asks first (Design, Tests) on its choices, open the next step, or Your program); **Redo** (`redoFirst`: `POST /catch-up` with `approve: false` for a stale step, one step of the open change with `approve: false` for a step the change has not reached); after a change from Your program its first step runs at once and Requirements opens for Accept |
| `api/client.ts`, `api/types.ts` | typed fetch wrapper; types mirror backend DTOs; errors become readable `ApiError` messages |
| `components/Sidebar.tsx` | brand, project switcher, `StepRail`, project views (Traceability, Folder with the number of hand edits, Activity, How it works), model line that opens Settings |
| `components/ProjectSwitcher.tsx` | current project with its progress mark and one line about where it stands (`where`: "Change #1: 2 of 6 steps", "Redo: 3 steps", "Step 2 of 6: Design", "Ready"), menu with all projects and "New project"; a bin per row (on hover, always on touch screens, disabled while an agent works) asks in place of the row "Delete X? ... Typing or pasting always works; a long path scrolls inside the field. `row` puts label, path and button on one line. Used on the start page and in the Folder view |

| `components/PhaseWorkspace.tsx` | one step screen: "Step n of 6", title, Result / Conversation switch, the marked sentence, the result (`Results`), the action bar (text box plus the one solid button and quiet links, or the working line with elapsed time). | `lib/flow.ts` | the guided flow as pure functions: `STEP_TITLE` (plain names), `redoOf` (backend `stale` plus the steps an open change has not reached, pipeline order), `stepMark`, `currentStep`, `autoStart` and `choosesFirst` (a generator without input starts on Accept; one with choices opens its step first), `afterAccept` and `acceptLabel` (what Accept does and says: "Accept and choose the diagrams"), `screen` (tab, marked sentence, primary and secondary acts, composer actions per state, `choices` on a step that asks first), `programState`. Every state is in `flow.test.ts` |
| `lib/choices.ts`, `components/StartChoices.tsx` | choices a generator offers before it runs (ADR 0018), read from its JSON schema: an `enum` is a radio group, an array of an `enum` a set of checkboxes, `default` is ticked, `option_hints` gives each option one line. Design: diagram kinds and level; Tests: focused or thorough. The step's solid button ("Draw the design", "Write the tests") sends what is ticked; with nothing ticked it disappears and the marked sentence says "Tick at least one diagram." |
| `lib/catchup.ts`, `lib/useUpdate.ts`, `components/RedoStrip.tsx` | "Redo all, accept when checks pass": `runUpdate` loops `POST /catch-up` with `approve: true` (one phase per call, at most 12; stops on `stopped_reason`, Stop, a refused request, or a call that changes nothing). `RedoStrip` shows the redo order on every step screen, the live run with Stop, and why a run stopped; it has no solid button |
| `components/Reply.tsx`, `lib/reply.ts` | agent replies: up to three lines whole; longer ones fold to the first paragraph plus any paragraph with a failure or an open question ("Show more"). `FoldList` and `DriftList` show three lines of a list and fold the rest, under a plain headline |
| `components/Conversation.tsx` | messages and the phase's system events in time order; quiet steps (the out-of-date record included) collapse per turn into one "Details" line, only errors stand alone; question cards with clickable answers; files a message was sent with; replies through `Reply`, the drift of a message through `DriftList`; copy button on agent replies; a live checklist while the agent works; a button back to the newest message; an empty chat shows one line about what the step makes |
| `components/RichText.tsx` | chat text: paragraphs, `- ` lists, `inline code`, and code blocks (fenced or indented by four spaces) that keep their indentation and scroll sideways; no HTML, nothing the text can inject |

## Behaviour worth knowing

- New actions in a wing need no frontend change in the API client, but the text box offers only the message actions `answer`, `start`, `revise`, `change`, `discuss` (`composerFor` in `lib/flow.ts`), labelled "Answer", "Describe it", "Change it", "Ask a question", plus `generate` in Tests as "Change the tests". Generators and checks are started by the solid button.
- New artifact kinds need a view component and a branch in `Results` of `PhaseWorkspace.tsx`; unknown kinds fall back to showing their text. Order: requirements, review, test results, injected bugs, deployment check, run guide, diagrams, files.
- Next steps: `data.next_actions` of the newest agent message become quiet buttons under it. A step for this phase without input runs at once; any other step opens its phase with the input in the text box (`prefill` in `App.tsx`).
- One loop for building and changing (ADR 0017). A result shows "Accept and <what comes next>"; Accept approves and starts the next step in the same `guarded` stretch, so the screen moves to the next step and shows "The coder is writing the code 0:12" until it is done. Design and Tests ask first (ADR 0018): Accept opens them on their choices, and their solid button starts the agent. Written tests are not run on their own: the step says "The tests are written but have not run yet." and offers "Run the tests".
- Redo: a step in the redo list never offers Accept. Its screen says why ("Requirements changed after this was made." or "Your change reaches this step.") and offers "Redo <step>" (made again without approval, then it waits for Accept) and the quiet link "Keep it unchanged". A step behind it points to the first one. A redo that stops only because its result now waits for Accept shows no notice; any other stop reason is shown as a quiet note.
- A change from Your program: `change` runs, then `GET /changes`; if the open change's next step is a run, `POST /changes/{n}/advance` with `approve: false` writes the requirement change at once and Requirements opens with "Accept and redo Design". From there the stale steps follow through the same loop. The change closes when every planned step has a new revision (backend).
- Trace navigation: a requirement's "In ..." links open the diagram in its phase; a diagram's covered IDs open the requirement and highlight it; a matrix row and "Follow REQ-..." under a requirement open that requirement's page in Traceability, which links on to every artifact in its phase and back to the requirement.
- Your program: after the last Accept the app opens Maintenance as Your program with Run it (the `run-guide` of Deployment, loaded with the step data) and What code checked. While the build or a redo is not done it says how far it is and "Continue with ..." / "Go to ..." leads on.
- Inject bugs: with a green test run that is current, the Tests screen offers "Inject bugs first" as a quiet link before Accept, and Your program offers "Inject bugs" in What code checked (`probe` in Tests; it never reopens an accepted step, ADR 0016). The marked sentence then says "All 7 tests pass. They caught 7 of 8 injected bugs." `api.trace` passes `strength` through as it comes: missing on an older backend, `null` when out of date or never run.
- While an agent works, every way to another phase is disabled (pipeline, view switch, project list, trace links, requirement chips), so a result always lands in the phase and project that asked for it. As a second guard, `App.tsx` keeps what the screen shows in a ref and drops any response that arrives for another project or phase (slow loads, quick clicks).
- If "Create and start" fails at the start step, the project exists and the description waits in its start composer.
- Selection groups (view switch, diagram tabs, composer actions) are buttons with `aria-pressed`, not ARIA tabs.
- Nothing typed is lost on failure: the composer clears the moment the developer sends (as chat apps do) and puts the text back if the backend refuses the action, unless the developer typed something new meanwhile; editors keep their draft when a save fails. Before s03 the text stayed in the box for the minutes an agent worked, which invited a second send.
- While an agent works, the progress line shows the time since the start (`useElapsed` in `Conversation.tsx`). If the project reports a `running` action this page did not send (sent before a reload, or in another tab), `App.tsx` shows that it is still running, disables sending, and asks `GET /projects/{id}` every 2 s until it has finished.
- Declared gaps: the results panel lists `known_gaps` artifacts with their requirement chips; the trace and the consistency table show `partly tested` and `not met` in amber; the test report names the requirements that do not count as verified despite passing tests.
- `GET /health` reports `api_version`; when it differs from `API_VERSION` (10) in `api/client.ts` the app shows "The backend runs older code than this interface". `api.trace` fills missing fields with defaults, so an older backend cannot crash a view.
- Documents: uploaded as soon as they are added (like a chat app), sent as ids with the next message. On the start page files wait until the project exists, then go up before P1 starts. The results panel lists every document of the project.
- Downloads: requirements as `requirements.md`, each diagram as its `.puml` source, each generated file under its name, all files of a phase as one text file.
- Start page folder: `NewProject` asks `onSuggestFolder(name)` (`api.defaultFolder`, `GET /system/default-folder?name=<project name>` returning `{"path": ...}`) at once and again 350 ms after the name derived from the description changed. Typing in the field or choosing with Browse ends the suggestions. If the call fails (older backend) the field stays empty and typing works. Without a folder the project cannot start: the send button carries `aria-disabled` and a tooltip that names what is missing ("Describe the software first", "Choose a project folder first"); a click or Enter then puts the cursor in the folder field and shows one amber line.
- Code: `GET /design-check` with the step data of Code and Your program. When code and class diagram differ, the marked sentence says so ("Checked by code") and the solid button is "Make the code follow the diagram" (a `revise` with the differences as feedback); "Accept anyway" is a quiet link.
- Tests: the text box asks a question by default (session s04: typing "run the tests" with Write tests selected wrote new tests twice); "Change the tests" in the switch writes them again with the typed guidance (`generate`, the depth kept). The switch was removed on 2026-11-25 and came back the same day, because without it asking was unreachable in Requirements, Design, Code and Deployment, and changing was unreachable in Tests. Design review has only "Ask a question" (it changes through its findings), so it shows no switch.
- Folder: a quiet note above the step appears when files in the project folder were changed by hand or the folder cannot be written, with Review (opens the Folder view). A message no agent wrote carries `data.speaker` ("Folder sync, checked by code"); its next steps work like an agent's. A message with `data.drift` shows "Resolved since" once `GET /design-check` says design and code agree.
- Fonts are bundled (`@fontsource/atkinson-hyperlegible-next`, `@fontsource/jetbrains-mono`); the app makes no request outside its own backend.

## Run

```bash
npm install
npm run dev          # 5190, proxies /api to 8810 (or to WINGS_BACKEND_PORT)
npx vitest run       # component and logic tests
npx tsc -b --noEmit  # typecheck
npm run build
```
